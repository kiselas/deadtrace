# Deadtrace repository audit and improvement plan

The 2026-10-01 audit found operational gaps that could hide unread source or crash a scan before
it returned useful diagnostics. Those gaps are fixed in ADR-0030. The next priorities are an
accurate analysis contract, independent quality measurements, and broader framework-version
evidence. Adding more framework heuristics before those measurements would make correctness
harder to assess.

## Repository and previous work

The audit started on `step-0-verdict-holes` at `d49b71d`, following the model-revision-22 changes
in `c03840b`. The only untracked file was `docs/methodology.md`. No other active Codex chat for
this checkout was found in the available chat listing. The previous agent's complete conversation
and checklist were unavailable, so this audit verifies the repository artifacts rather than
claiming every previous intention was fulfilled.

The inherited implementation passed the baseline gate: 310 tests passed, two skipped, and coverage
was 92.63%. The methodology draft has been preserved and reviewed: its precision metric is
corrected, private measurements are identified as unreproduced historical evidence, and proposed
coverage/confidence features preserve the rule that absence of execution does not prove deadness.
It remains a proposal, not an accepted implementation track.

The local `.venv` referred to a removed uv-managed Python 3.12.14. Reinstalling that managed
interpreter failed twice in uv's minor-version-link setup. Recreating the project environment
with the already installed CPython 3.12.4 succeeded; all checks below use that interpreter.
The lockfile and dependencies were not changed.

## Findings and completed fixes

| Priority | Evidence before the fix | Result |
| --- | --- | --- |
| P0 | `os.walk` ignored denied directories. A readable main script beside a denied directory could still yield a complete report and negative findings. | Directory failures are `DT1001`; readable definitions survive, worlds become partial, and the CLI exits 2. Transient discovery failure retries the entire snapshot. |
| P1 | A source cookie naming `base64_codec` or `hex_codec` raised an uncaught `LookupError`. | Source read and verification emit `DT1001` and preserve other files. |
| P1 | Invalid UTF-8 in configuration or metadata raised an uncaught decoding exception. Configuration reads had no size bound. | Configuration gives exit 2 and reads at most 16 MiB plus one detection byte. Metadata readers use their established malformed-input policies. |
| P1 | `version = "oops"` in a lock file or `fastapi===oops` in project requirements raised `InvalidVersion`. | An invalid version of an imported modeled dependency produces `DT4001`, withholds findings, and fails `--require-complete`. Unmodeled dependencies make no framework compatibility claim. |
| P1 | The distribution check exercised only `--version`. | The portable wheel smoke checks inventory, complete analysis, deterministic JSON, saved explanations, baselines, comparisons, diagnostic exit codes, and no target execution or source mutation. CI uses it on both operating systems. |

Twelve new regression scenarios cover these input failures and controls. Six failing scenarios
were reproduced before the first fixes; malformed framework versions were separately reproduced
as a direct reader crash. No `CASE.md` or `CASE.toml` expectation was changed. The model stays at
revision 22; these fixes enforce existing operational and compatibility contracts.

## Remaining weaknesses and ordered plan

| Order | Work | Evidence and completion criterion |
| --- | --- | --- |
| 1 | Reconcile the active milestone and publish the analysis contract. | `AGENTS.md` says inventory-only PR-01; the implementation and ADR-0029 are at model revision 22; `ROADMAP.md` still records revision 15 and 63 semantic projects. README lists the contract, architecture, support matrix, and acceptance matrix as pending. Accept a bounded scope decision in an ADR, then align these documents with executable evidence. Do not silently promote the milestone. |
| 2 | Make remaining metadata and artifact reads bounded and consistent. | Entry-point, dependency, deployment, and JSON readers check file size before an unbounded read. A file can grow between those operations. Dependency metadata also treats unreadable, malformed, and absent inputs alike. Define explicit failure policies, enforce limits on the actual read, and test growth and changes between metadata passes. The new configuration reader is already bounded. |
| 3 | Establish a reproducible public development and held-out scoreboard. | ADR-0025 records 44 false findings out of 88 before fixes; ADR-0026 records 29 out of 86; ADR-0028 records about a third of 299. These are useful mechanism discoveries, not a stable precision estimate. Pin inputs and versions, keep fixes out of the held-out set, and measure precision and recall separately by definition kind. Any execution oracle requires its own opt-in runner and threat model. |
| 4 | Verify framework support across the declared ranges. | FastAPI `>=0.100,<1` and Dishka `>=1,<2` are claimed, while the runtime oracle pins only 0.141.1 and 1.10.1. Add independently justified compatibility samples for range boundaries and materially different versions. Run complete positive, negative, and guarded cases in those environments before widening claims. |
| 5 | Refactor framework fact collection after contracts are pinned. | `python_frontend.py` has 4,151 lines, `frameworks.py` 3,483, and `pytest_semantics.py` 1,299. Extract cohesive pure fact collectors one at a time. Require byte-identical valid-input reports and unchanged corpus outcomes; avoid a speculative plugin architecture. |
| 6 | Measure large-project report and memory costs before changing schemas or adding caches. | ADR-0022 records a 624k-line monorepo around 70 seconds and a 113 MB report. Current 50k synthetic budgets pass, but do not measure that shape. Pin representative world/guard-heavy inputs, profile report rendering and solver memory, then propose deduplication or compact facts in an ADR. |

The steps above are proposed follow-up work. This audit closes input integrity and verification
gaps without starting another semantic milestone. Private pilot claims were not independently
revalidated. In ADR-0029, the reported total of 1,614 reviewed members differs by one from
1,110 true plus 503 false; reconcile that with the private ledger before publishing a precision
number, rather than guessing the missing classification.

## Verification

Local evidence is Windows with CPython 3.12.4. Linux runtime checks were not run locally; CI remains
the required cross-platform confirmation. The two pytest skips concern unavailable Windows symlink
privileges and an empty known-violation parameter list.

| --- | --- |
| `uv sync --locked --all-groups` and `uv lock --check` | Pass with the restored environment |
| Ruff check and format check | Pass |
| Strict mypy, Windows and `--platform linux` | Pass |
| `uv run pytest --cov` | 322 passed, 2 skipped; branch-aware coverage 92.72% |
| Seed case validator | 6 cases, 12 lexical targets |
| Semantic case validator | 112 cases, 397 lexical targets, 112 semantic manifests |
| `uv build` | Wheel and source distribution built |

The scale generator writes 50,000 lines and the service generator 50,044. Benchmark counters count
each file's trailing line and report 50,251 and 50,226 respectively. Each fixture ran three times,
sequentially, after the test run, from the installed wheel outside the source checkout:

| Fixture | Analysis seconds per run | Median seconds | Maximum peak RSS |
| --- | --- | --- | --- |
| Scale | 10.08, 1.82, 1.80 | 1.82 | 86.00 MiB |
| Service | 14.09, 4.28, 4.15 | 4.28 | 147.39 MiB |

First-run costs are visibly higher. These are synthetic performance guards on this host, not proof
of field precision, scalability to every project, or an improvement over the historical baseline.
Raw source-free artifacts are in [benchmarks/results/audit-2026-10-01](../benchmarks/results/audit-2026-10-01/).
The budget checker passed on all six artifacts.

Reproduce the functional distribution check after building:

```console
uv run --isolated --no-project --python 3.12 --with ./dist/deadtrace-0.1.0a0-py3-none-any.whl python scripts/wheel_smoke.py
```

The smoke script creates its own temporary working directory and rejects a package imported from
the checkout. For benchmark reproduction, follow `benchmarks/README.md` with three fresh processes
per fixture and retain the raw artifacts.
